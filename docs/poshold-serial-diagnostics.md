# USB 串口定点诊断

此工作区增加了只读串口诊断，用于排查“机身静止、光流接近零，但估算速度增长”。不需要连接飞机 Wi-Fi，不需要起飞。诊断本身不发送控制命令。2026-10-22 已完成架高静止数据采集，并据此增加地面重力方向校正；修复后的实机复测尚未完成，详见 `poshold-serial-findings-2026-10-22.md`。

## 烧录和监视

在 ESP-IDF 终端、项目根目录执行：

```bat
idf.py -p COM9 -b 115200 flash
idf.py -p COM9 -b 115200 monitor
```

串口使用 115200 波特率，按 `Ctrl+]` 退出监视器。烧录前关闭占用 COM9 的监视器。根目录 `partitions.csv` 已补回仓库原有布局（应用从 `0x10000` 开始，每个 OTA 应用分区 `0x140000` 字节），不要删除。只在 `flash` 成功后读取新版数据。

拆桨、保持电机停转，上电时水平静置完成 IMU 校准。先记录静止状态；再保持机头朝向和高度，沿前、后、左、右分别移动。光流和测距传感器下方应无遮挡，使用有纹理且光照稳定的地面，可用稳定支架使传感器离地约 30～50 cm。桌面紧贴传感器的测量结果不能代替此高度的光流测量。

## 输出含义

估算器每约 200 ms 发布快照；独立低优先级任务负责串口打印。单元素覆盖队列避免串口消费慢时阻塞估算任务，来不及输出的中间快照可能跳过。一次快照有三行，`t` 相同，单位为上电后的毫秒。估算、光流采样仍按原周期运行，不是每 200 ms 才更新传感器。

| 前缀 / 字段 | 含义 |
| --- | --- |
| `POSHOLD_STATE pos_mm` | 世界坐标位置 x、y、z，毫米 |
| `vel_mm_s` | 世界坐标速度 x、y、z，毫米/秒 |
| `body_vel_mm_s` | 估算器内部机体坐标速度 x、y、z，毫米/秒；x 为前向 |
| `att_cdeg` | 横滚、俯仰、偏航，除以 100 得到度；沿用项目姿态符号约定 |
| `range_mm` / `fresh` | 向下测距，毫米；是否在 300 ms 内有效更新，1 为真 |
| `bounds` | 累计触发越界重置次数，不受原先约 2 秒日志限频影响 |
| `counts` | 累计预测次数、实际取出处理的光流包数、实际处理的测距包数；相邻差除以时间可看处理频率，不代表测量一定准确 |
| `POSHOLD_IMU body_acc_mg` | 送入估算器的机体系加速度，含重力；1000 为 1 g，不是未经驱动处理的原始寄存器值 |
| `world_acc_mg` | 世界系去重力加速度，1000 为 1 g；机身静止时应接近零 |
| `gyro_mdps` | 机体系角速度，除以 1000 为度/秒 |
| `gravity_align` / `gravity_updates` | 地面重力对齐当前是否启用 / 自最近一次估算器初始化以来的累计校正次数；停桨架高静止后前者应为 1，后者持续增加 |
| `gravity_quiet_ms` | IMU 与连续光流窗口的静止确认累计时间，分别以毫秒表示；两者至少达到 500 ms 才启用对齐，计时饱和在约 1000 ms |
| `POSHOLD_FLOW window_ms` | 本次输出与上次输出的间隔；首条从上电累计，分析时可跳过首条 |
| `seen` / `submitted` | 是否见过帧 / 最新帧是否通过驱动筛选并调用提交接口。当前底层接口在队列满时仍返回真，因此提交不等于成功融合；结合 `counts` 中实际处理数判断 |
| `motion` / `squal` / `shutter` | 最新帧状态字、地面特征质量、曝光值；`motion` 最高位仅代表有运动，零位移有效帧也会提交 |
| `dxy` / `dt_us` | 最新帧映射到机体轴的 dx、dy 像素位移及帧间隔（微秒），不是整个输出周期的位移 |
| `age_ms` | 最新读取帧 / 最新提交帧的年龄，毫秒；4294967295 表示未见过对应帧 |
| `frames` | 输出间隔内读取帧数、提交帧数 |
| `sum_dxy` | 输出间隔内所有读取帧的 dx、dy 累计，包含被筛除帧 |
| `submitted_dxy` / `submitted_us` | 输出间隔内通过驱动筛选并提交的帧的累计 dx、dy 及累计帧间隔（微秒），避免低频抽取最新一帧漏掉中间运动 |
| `POSHOLD_BOUNDS` | 次数变化时额外输出最近一次越界前的位置和机体速度，以及发生时刻 `last_t`；两次报告间多次触发时保留最新值和累计次数 |

整数缩放字段出现 `-2147483648` 表示非有限值或超出诊断表示范围。默认位置任意轴超过 ±100 m 或机体速度任意轴超过 ±10 m/s 会触发越界重置；具体以运行参数为准。

先比较静止时的 `body_vel_mm_s`、`world_acc_mg`、`submitted_dxy` 和实际光流处理次数，再判断是加速度/姿态偏差、光流有效性、比例/方向还是融合问题。仅看到 dx、dy 为零，不能判定硬件损坏，也不能判定估算器已经正确利用零流量。

## 重力对齐修复后的静止复测

烧录当前工作区固件后，沿用原来架高约 20 cm 的稳定支撑和有纹理平面，拆桨、停电机，打开 monitor，放稳后记录 30～60 秒。无需连接飞机 Wi-Fi，也无需起飞。

1. 确认 `POSHOLD_IMU` 行出现 `gravity_align` 字段，证明正在运行包含本次修改的固件。
2. `fresh=1`、测距与实际传感器高度接近、`counts` 的光流处理数持续增加。重力对齐要求有效测距为 8 cm～3 m，不能紧贴桌面。
3. 静止确认至少约 0.5 秒后，应出现 `gravity_align=1`、`gravity_updates` 持续增长。若一直为 0，先检查测距、光流有效性、支撑晃动及角速度，不将此状态当作已经校正。
4. 比较最后 10～30 秒 `body_vel_mm_s` 的水平两轴是否围绕零小幅波动、`world_acc_mg` 是否明显减小，以及是否新增 `bounds`。原静止记录平均前向/左向速度为约 36/122 mm/s，可作为对照；尚未测得本次固件的真实结果。

这一步只验证静止估计。完成后再拆桨做定向平移，最后才评估实飞后漂；离线测试的亚毫米每秒结果不是实机精度承诺。
